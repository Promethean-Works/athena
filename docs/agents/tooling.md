# Agent tooling

_How the coding agents (Claude Code, OpenCode, Hermes Agent, Codex, Antigravity, Copilot) are set up for this repo. Read this when you change agent tooling (MCP servers, skills, generated agent config) or set up a machine. Day-to-day work doesn't need it._

## One source of truth

Everything agent-related has one source of truth in the repo; each agent reads it directly or through a link or a file generated by `scripts/agents-sync.mjs` (CI runs `--check`, so generated files can't drift).

| What | Source of truth | How each agent gets it |
|---|---|---|
| Instructions | `AGENTS.md` (router) + `apps/*/AGENTS.md` | Claude Code through `CLAUDE.md` files that import them; the others read `AGENTS.md` directly |
| Area gotchas | `docs/agents/gotchas/<area>.md` | Claude Code `.claude/rules/<area>.md` and Copilot `.github/instructions/<area>.instructions.md` (generated from `AREA_RULES`) point at them when a matching file is touched; everyone else follows the router |
| Skills | `.agents/skills/` (third-party ones pinned in `skills-lock.json`) | Claude Code through the `.claude/skills` symlink; OpenCode, Codex, Antigravity and Copilot read it; Hermes after `hermes skills trust` |
| MCP servers | `.mcp.json` | Claude Code and Copilot read it; generated `opencode.json`, `.codex/config.toml`, `.agents/mcp_config.json` (Antigravity); Hermes through `agents-sync.mjs --hermes` |
| Subagents | `OPENCODE_SUBAGENT_ONLY` in `scripts/agents-sync.mjs` | Generated `.claude/agents/*.md` and agents in `opencode.json` |
| Machine settings (RTK, TokenEconomizer, Hermes trust, opt-in models) | `scripts/agents-setup.mjs` + templates in `.agents/user/` | Applied to the home folder by `node scripts/agents-setup.mjs` (see [New machine](#new-machine)) |
| Project state | `docs/STATUS.md` (finished work: `docs/HISTORY.md`) | Read at the start of every session |

## How each agent loads instructions

Checked against each tool's docs (Hermes: its source) on 2026-11-19. This is why `AGENTS.md` is a router and the app folders have both files.

| Agent | Reads | Subfolders |
|---|---|---|
| Claude Code | `CLAUDE.md` only, once a root one exists (so the root and each app `CLAUDE.md` import `@AGENTS.md`) | A subfolder `CLAUDE.md` loads the first time a file there is read or edited <!-- docs-check: ignore --> |
| OpenCode | `AGENTS.md` (`CLAUDE.md` only where a folder has no `AGENTS.md`) | Loaded when a file below is read or listed |
| Hermes Agent | `AGENTS.md` chain from the git root to the cwd; `CLAUDE.md` is ignored when `AGENTS.md` exists | Added to the tool result the first time a path there is touched |
| Codex | `AGENTS.md` from the repo root down to the cwd, 32 KiB in total | Never below the cwd: it follows the router |
| Antigravity (ex Gemini CLI) | `AGENTS.md` and `GEMINI.md` | When a tool touches a file there <!-- docs-check: ignore --> |
| Copilot | `AGENTS.md` (nearest wins), `.github/copilot-instructions.md`, `.github/instructions/*.instructions.md` | Along the paths it works with <!-- docs-check: ignore --> |

## MCP servers (`.mcp.json`)

- `shadcn`: browse, search and install registry items.
- `next-devtools`: Next.js docs and runtime diagnostics while `pnpm dev` runs.
- `playwright`: a headless browser with an in-memory profile, for UI verification (navigate, accessibility snapshots, screenshots in `.playwright-mcp/`, clicks, console, network, resize). It runs with `--snapshot-mode none` to save tokens: actions don't return the page, so call `browser_snapshot` when you need it. It uses the system Chrome; on a machine without Chrome, add `--browser firefox` or install Chrome.
- `context7`: current docs and examples for any library (FastAPI, SQLModel, Alembic, wsgidav, xterm.js, Base UI, pydantic-ai, rclone…). It works without an API key (rate-limited); set `CONTEXT7_API_KEY` for higher limits.

## Skills (`.agents/skills/`)

Third-party ones are pinned in `skills-lock.json`: `shadcn`, `building-pydantic-ai-agents`, `pydantic-ai-harness`, `pydantic`. The project's own skills are routed from `AGENTS.md` → Read when. All skills are committed, so a clone has them.

## Changing tooling

- *Add an MCP server:* edit `.mcp.json`, then run `node scripts/agents-sync.mjs` to regenerate every agent's copy (and `--hermes` to update Hermes). Never edit generated files or parts by hand: the `mcp` block of `opencode.json`, its `playwright_*` permission rules and `ui-verify` agent, `.claude/agents/`, `.claude/rules/`, `.github/instructions/`, `.codex/config.toml` and `.agents/mcp_config.json`. Which tools each agent gets is set in `scripts/agents-sync.mjs` (`UNUSED_TOOLS`, `OPENCODE_SUBAGENT_ONLY`). CI runs `--check`.
- *Add a third-party skill:* `npx skills add <owner/repo> --skill <name> -a claude-code -y`. It lands in `.agents/skills/` through the symlink and is recorded in `skills-lock.json`.
- *Add a project skill:* create `.agents/skills/<name>/SKILL.md` with `name` and `description` frontmatter (the description is what agents see before loading the skill: say what it does and when to use it), and add it to the list in `AGENTS.md`. `scripts/check-docs.mjs` checks every name the skill mentions.
  - Hermes's scanner also hides **our own** skills when they contain `curl … | python3` (rated critical "supply chain"), even when Python only parses JSON. In skills, use `jq` or save to a file first. `sudo`, `uv run` and systemd mentions are only medium and don't hide a skill. To check a skill before committing: `PYTHONPATH=~/.hermes/hermes-agent ~/.hermes/tools/python-3.14*/bin/python3 -c "from pathlib import Path; from tools.skills_guard import scan_skill; print(scan_skill(Path('.agents/skills/<name>'), source='project').verdict)"` should print `safe`.
- *Add a gotchas area that loads by itself:* add the file under `docs/agents/gotchas/`, then its globs to `AREA_RULES` in `scripts/agents-sync.mjs`, and run the script.
- *Change a machine-level setting* (a hook, plugin or user config every agent install needs): add a step to `scripts/agents-setup.mjs` (with a check, a fix that merges rather than overwrites, and a manual fallback), keeping its data in `.agents/user/` without secrets.

## New machine

1. Install the agents you use and sign in to each (and `gh auth login`). Put API keys in your environment or the agent's own login; none are in the repo.
2. Clone the repo and run `node scripts/agents-setup.mjs` from it. It lists what's missing for the agents found on `PATH` and, after you confirm, fixes it:
   - git hooks (`core.hooksPath`);
   - RTK (installed with brew or cargo) and its hook in Claude Code, OpenCode and Hermes;
   - TokenEconomizer (cloned to `~/.local/share/TokenEconomizer` or `$TOKENECONOMIZER_DIR`, plugin installed in Claude Code, linked into OpenCode and Hermes, `TE_PYTHON` set to a Python 3.10+);
   - Hermes: trusts the repo's skills and registers the MCP servers;
   - with `--with-models`, the maintainer's provider and model choices from `.agents/user/` (OpenCode and Hermes).
   `--check` only reports, `--dry-run` prints the commands, `--yes` skips the question, `--only <groups>` limits it. Re-running is safe: it merges into existing configs.
3. Restart each agent (Hermes: also `/reload-mcp`).

Claude Code runs `agents-setup.mjs --check --quiet` at every session start (`SessionStart` hook in `.claude/settings.json`) and says what's missing; other agents are told to by `AGENTS.md`. An agent must ask before running the fixes, since they install tools and edit the home folder.

Per agent, what the script doesn't do:

- **Claude Code** on Windows: enable symlinks (`git config core.symlinks true` with Developer Mode on) so `.claude/skills` works.
- **OpenCode:** a cheaper model for the `ui-verify` subagent, in your own `~/.config/opencode/opencode.json`: `{"agents": {"ui-verify": {"model": "<provider>/<model>"}}}`.
- **Hermes Agent:** its skill scanner rates `pydantic-ai-harness` "dangerous" (a false positive from docs mentioning `~/.ssh` and `os.environ`) and hides it; read `.agents/skills/pydantic-ai-harness/SKILL.md` directly when working on the assistant. Hermes trusts folders by path, so a worktree outside the trusted checkout doesn't get the project skills.
- **Codex:** trust the project when asked, or `.codex/config.toml` is ignored. RTK has no Codex hook; TokenEconomizer: its README → Codex.
- **Antigravity:** `rtk init --agent antigravity --hook-only`; TokenEconomizer: its README → Antigravity CLI.
- **Copilot:** nothing; it reads `AGENTS.md`, `.mcp.json`, `.agents/skills` and `.github/instructions/` from the repo.

## Token budget

In the repo:

- **What every session pays for is kept small:** `AGENTS.md`, STATUS and the app rule files are size-capped by `scripts/check-docs.mjs` (`SIZE_LIMITS`) (finished work goes to `docs/HISTORY.md`); `scripts/check.sh` is quiet without a terminal; Playwright runs with `--snapshot-mode none` (snapshot only when you need to read the page); `.ignore` keeps lockfiles, CHANGELOG and the generated theme files out of ripgrep searches; Claude Code caps Bash and MCP output at 20k (`.claude/settings.json` → `env`) and OpenCode caps tool output at 20 KB (`opencode.json` → `tool_output`, the rest is saved to disk). Pipe long commands through `tail` or `grep` yourself too. This file is separate from AGENTS.md because only tooling changes need it.
- **Dependencies ship their own agent files.** pydantic-ai has `CLAUDE.md`/`AGENTS.md` files in `.venv/…/pydantic_ai/` (about 40 KB, written for pydantic-ai's own contributors), and Next and recharts ship `AGENTS.md` in `node_modules`. Claude Code loads a subfolder's `CLAUDE.md` as soon as it reads a file there, which happens when you read pydantic-ai's source. `.claude/settings.json` → `claudeMdExcludes` skips them. <!-- docs-check: ignore -->
- **MCP tool definitions cost tokens on every request in OpenCode and Hermes** (Claude Code loads them on demand). Measured: Playwright 25 tools ≈ 21k characters, next-devtools ≈ 5.7k, context7 ≈ 5.2k, shadcn ≈ 4.3k. So `scripts/agents-sync.mjs` gives Playwright only to OpenCode's `ui-verify` subagent (a `playwright_*` deny rule globally, allow in the agent; agent rules come after global ones and the last match wins), and writes Hermes `tools.exclude` filters for unused tools. OpenCode 2.x already routes MCP tools through Code Mode by default (`codemode: true`). Hermes' `lazy: true` only delays connecting; the tools are still registered, so it saves memory, not tokens.

Per person, so not committed:

- **A cheaper model for browser checks.** Claude Code's generated `ui-verify` subagent uses `model: sonnet`; OpenCode's needs a per-provider id (see New machine → OpenCode).
- **Token-saving tools (set up by `scripts/agents-setup.mjs`):**
  - [RTK](https://github.com/rtk-ai/rtk) (Apache-2.0): a hook that shortens the output of shell commands like `git`, `gh`, `pytest` and `pnpm` before the agent reads it. Works with Claude Code and OpenCode. It only covers shell commands (not built-in Read or Grep), and it runs your commands through a third-party binary. `scripts/check.sh` is already quiet without a terminal, so the gain here is mostly on `git`, `gh` and ad-hoc test runs.
  - [TokenEconomizer](https://github.com/microsoft/TokenEconomizer) (Apache-2.0): learns repo facts, prunes unused tools, and nudges an agent stuck in a failure loop. The first two overlap with `athena-recipes`, the command cheat sheet and the MCP scoping above. What it learns stays in `~/.tokeneconomizer`, so anything another agent needs must still go in the repo.
  - Both are installed and hooked into each agent by `scripts/agents-setup.mjs` (see [New machine](#new-machine)). `rtk gain` shows RTK's savings; `~/.tokeneconomizer/bin/te doctor` checks TokenEconomizer. RTK runs with `--hook-only` (no `RTK.md`, an instructions file every session would pay for). TokenEconomizer's tool pruning writes `.claude/settings.local.json`, which is git-ignored. <!-- docs-check: ignore -->
  - Not used: caveman (terse replies; measured at a few percent of a session's tokens, and the "Short replies" rule in `AGENTS.md` gets most of it).
