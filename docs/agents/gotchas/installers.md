# Gotchas: Installers and E2E

- Hosted runners can't run Colima's VM (macOS) or WSL2 (Windows), so containers are only checked end to end on Linux in CI.
- For a full Linux check locally on a Mac, use a Lima VM (`limactl start template://ubuntu`, or `template://fedora` for dnf). Docker containers don't run systemd, so they can't test the service.
- Installers take `--wheel <path>` / `-Wheel <path>` so E2E tests the commit, not the last release.
- Recording pacman fixtures under amd64 emulation on Apple Silicon needs `--disable-sandbox` (for recording only).
- There's no `athena service restart`. `athena service install --data-dir <dir>` restarts the service on every OS (systemd `restart`, launchd `bootout` + `bootstrap`, Windows stops the interpreter and `/Run`s the task), so the E2E workflow uses it. Pass the same data dir the installer used.
- The service unit has no `--port`: the port is `server.port` in `<data-dir>/athena.json`, so editing the file and restarting is enough. `service install --port N` saves it there. A `--port` in the unit would override the file and make hand edits do nothing.
- macOS: `launchctl bootout` returns before the agent is gone, and a `bootstrap` right after fails with "Bootstrap failed: 5: Input/output error". Every reinstall over a running agent (upgrades, restarts) hit it, and only the E2E HTTPS step exposed it. `_launchd_bootout` (`service/platforms.py`) waits until `launchctl print` no longer finds the agent.
- Self-update (`athena update`) takes the tool dir, bin dir and Python dir from the install's own uv receipt and passes them to uv as `UV_TOOL_DIR`, `UV_TOOL_BIN_DIR` and `UV_PYTHON_INSTALL_DIR`, because the installers keep Athena's uv state in Athena-owned folders; plain `uv tool install` would make a second install in `~/.local`.
- The swap runs from a copy of `update_helper.py` with the *base* Python (`uv python find 3.13`) and `-I`: nothing it runs may live in the tool venv it replaces. The install uses `--offline`, which only works because the pre-flight (`uv tool run --from <wheel>`) already put the dependencies in uv's cache; the previous version's wheel is pre-flighted too, so a rollback is offline-safe.
- On Windows `athena update` can't wait for the helper (the running `athena.exe` holds the venv open), so it starts the helper detached and exits 0; `scripts/e2e/update_check.py` polls the helper's state file instead. Part 1 verified Linux in a Lima VM; macOS and Windows are checked only by the E2E `update` job. The helper isn't yet started detached from the *server* (part 2).
