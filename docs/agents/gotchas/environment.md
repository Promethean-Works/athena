# Gotchas: Agent environment

- Agent tooling quirks (token budget, MCP tool costs, Hermes's skill scanner, agent files shipped by dependencies) are in `docs/agents/tooling.md`.
- The maintainer's shell is zsh. `echo =====` fails there (`=word` expands to a command path), and unquoted `$VAR` lists don't word-split. Quote or use arrays.
- Claude Code's safety check refuses `rm` with unguarded variables or globs (`rm -rf $S/*`). Use literal paths.
- Several agent sessions run at once, so every task gets its own worktree (`git worktree add ../worktrees/athena-<topic> -b <branch> origin/main`) and the base checkout stays on `main`. Agents used to follow `git switch -c` in the base checkout from older docs; `scripts/pre-commit.sh` now rejects commits from the base checkout (git-dir equals git-common-dir), and `scripts/agent-guard.mjs` refuses the edits themselves (one agent still left uncommitted changes there in 2026-11).
- The machine can be offline (no DNS, even outside the sandbox). `uv run --offline --with <pkg>==<version>` uses uv's cache when the package was installed before.
- `pkill` and `ps` may fail in the sandbox ("Cannot get process list"). Find a server by its port with `lsof -nP -t -iTCP:<port> -sTCP:LISTEN` and `kill` that pid.
- VS Code: `.vscode/launch.json` (debug the server, pytest, Next with Chrome, or both as "Full stack") and `.vscode/tasks.json` (dev, build, release serve, tests, checks, codegen). Data goes to the git-ignored `.dev-data/`.
- Port 8420 may be the maintainer's own Athena. Use 8421 or another spare port.
- Act only on containers, apps and images named `athena-demo-*` / `athena-test-*`. The maintainer's own containers run on the same engine. Leave pulled images unless you know you pulled them, and say which ones are left.
- The pre-push hook runs the web checks when any file under `apps/web` changes, `apps/web/AGENTS.md` included. A docs-only push can then fail on a local web problem. Check that the diff is docs only (`git diff main --name-only`) before using `--no-verify`, and let CI decide.
- A full disk stops every shell command from starting (ENOSPC on Claude Code's temp folder), and Colima's VM disk then fails with `input/output error` on `containerd/.../meta.db`. After you free space, run `colima restart` before Docker works again.
- `import pydantic_ai.mcp` failing with "Please install the fastmcp client" doesn't mean fastmcp is missing. Both that module and fastmcp's own client package catch the real `ImportError` and replace it. Read the first exception in the traceback before reinstalling anything (once the cause was a full disk, with every package installed).
- `mcp` and `fastmcp` major versions move together: fastmcp 3.x needs `mcp<2`, fastmcp 4.x needs `mcp>=2.3`. A Dependabot bump of only `mcp` lets uv fall back to fastmcp 2.14 (no `mcp` cap), which fails with "cannot import name 'McpError'". Bump both bounds in `apps/server/pyproject.toml` together (#164).
- Claude Code's auto-mode classifier may refuse running a binary you just downloaded by hand (it did for lego), while the app downloading and running it during a browser check went through. Read the tool's source/docs for its CLI instead (lego v5's flags differ from v4: `lego run` both issues and renews).
- A "read-only" reviewer subagent can still write files: OpenCode's `edit` deny and Claude Code's missing edit tool leave `shell` (and OpenCode's Code Mode `execute`) open. An OpenCode reviewer told to test it appended to a file (2026-11-25). Unattended reviews run in their own worktree and are discarded when it changed (`docs/agents/tooling.md` → Running agents headless).
- The base checkout's HEAD moves by itself: VS Code's Git sync runs `git pull --tags origin main` now and then (seen in its reflog). Anything that checks "the base checkout didn't change" must allow a fast-forward, but only to a commit already on `origin/main` after a fresh fetch (a local commit on `main` is also a fast-forward), and compare branch and uncommitted changes strictly (`scripts/orchestrate.mjs` → `unchanged`); a strict HEAD check blocked a correct worker run (#280).
