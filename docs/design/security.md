# 7. Security baseline

- Binds to LAN by default. First run forces the admin account to be created before anything else is reachable.
- Public routes (no session): `/api/health`, `/api/auth/*`, share links (`/api/public/shares/{token}`, `/s/{token}`), the automation webhook `POST /api/automation/webhook/{token}` (the trigger's random token is the credential) and `/api/mcp` with the `ATHENA_MCP_TOKEN` bearer (acts as the admin; a session cookie works too). `/dav/` has its own sign-in. Everything else needs a session.
- Session cookies are `HttpOnly` and `SameSite=Strict`, with CSRF tokens on mutating requests and login rate limiting.
- The terminal, package installs and the assistant's shell are the most powerful features. They're admin-only and every use is written to the audit log. The terminal (Settings → System) and the assistant's shell (Settings → AI, off by default) can be turned off; package installs have no off switch yet.
- Remote access tunnels (§4.8) put the UI on the internet: off by default, admin-only, with their tokens encrypted at rest.
- The rclone rcd and container sockets are never exposed beyond localhost.
- Secrets: AI provider keys, integration tokens and tunnel tokens are encrypted at rest (Fernet) with a key file `<data-dir>/secret.key` (0600), not the OS keyring, which headless Linux hosts usually lack (M7, see §4.5). The rclone config is a 0600 file in a 0700 folder, with passwords obscured by rclone (reversible, not encryption). See §11.

## HTTPS

Spec: `docs/specs/https.md`. Code: `athena/https/`, `api/https.py`, Settings → HTTPS (`apps/web/components/settings/https-settings.tsx`).

- **Two listeners, one app.** HTTP stays on `port` (8420). When a mode is on, a second `uvicorn.Server` serves the same app over TLS on `https_port` (8443) with `lifespan="off"`, so startup tasks run once. `HttpsManager` (`https/manager.py`) starts, moves and stops it in process when the settings change; a bad port is refused before anything is saved, so the UI stays up. New certificates are loaded into the running `SSLContext` (no restart).
- **Modes.** `off`, `self_signed` (Athena's local CA, `https/local_ca.py`: EC P-256 CA for 10 years, a 365-day server certificate naming `localhost`, the hostname, `<hostname>.local`, every interface address and the extra names; reissued by the daily check when under 30 days or the addresses change) and `letsencrypt` (below).
- **Settings** are their own `system_settings` row (`https`, `https/settings.py`), apart from Settings → System, so `athena https off` can change them alone. DNS provider tokens are encrypted with `SecretBox` and never returned. Keys and certificates live in `<data-dir>/tls/` (folder 0700, keys 0600, not encrypted: uvicorn reads plain files).
- **Redirect** (`https/redirect.py`): only browser page loads on the HTTP port get a 307 to HTTPS. API calls, WebDAV, WebSockets, requests from loopback and requests through a proxy or tunnel (`X-Forwarded-*`) are served as before, so `curl http://127.0.0.1:8420`, the CLI, containers and tunnels keep working. No HSTS.
- **Let's Encrypt** (`https/letsencrypt.py`, `https/lego.py`): the lego binary (MIT, pinned version and per-archive SHA-256 in `lego.py`, downloaded by `athena/downloads.py` into `<data-dir>/bin/`, its hash rechecked before each run) does the ACME work. `lego run` both issues and renews. HTTP-01 needs port 80: the job checks it can open it before running lego, and the status reports `port80_free`. DNS-01 goes through the `https/dns_providers.py` table (Cloudflare first); credentials reach lego only in its from-scratch environment. Getting a certificate is a job; the daily check (and one a minute after start) renews within 30 days, and a failure keeps the old certificate. The last renewal and error are kept in memory only.
- **Ways back in**: `http://127.0.0.1:8420` is never redirected, and `athena https off --data-dir …` turns HTTPS off for the next start. The assistant has only a read-only `https_status` tool.
- **Testing hooks**: `ATHENA_ACME_DIRECTORY`, `ATHENA_ACME_CA_CERTIFICATES` and `ATHENA_ACME_HTTP_ADDRESS` point lego at Pebble. CI runs it with validation always passing; `athena-host-test` has the recipe with real port-80 validation. `scripts/e2e/https_check.py` checks self-signed HTTPS on an installed host (E2E workflow on Linux, macOS and Windows).
